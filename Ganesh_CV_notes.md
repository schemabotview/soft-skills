## 3. Last 3 Projects — Briefs

### Barclays — Global Banking Data Platform (Nov 2025 – Present)
Lead Data Engineer on a global banking data platform, delivering ELT pipelines for trade finance,
risk analytics and regulatory reporting, with two data engineers reporting in.

Built Azure Databricks PySpark pipelines joining trade-finance transactions, counterparty
hierarchies, credit limits, collateral positions and exposure data from core banking systems,
publishing reconciled datasets to ADLS Gen2 for Risk and Regulatory Reporting. Added a
near-real-time trade-risk flow on Kafka + PySpark Structured Streaming — event validation,
deduplication, watermarking and aggregation — feeding intraday counterparty and market-risk
exposure calculations. Regulatory transformation layers for **Basel III and FRTB** were designed in
Delta Lake using PySpark/SQL business rules with Delta MERGE and historical versioning for
auditable reporting. FCA/PRA reconciliation was re-engineered in Microsoft Fabric — source
freshness checks, relationship tests, reconciliation models and exception datasets — replacing
spreadsheet-driven validation. Orchestration was split across Airflow dependency graphs and Azure
Data Factory (ingestion / regulatory transformation / reconciliation / publication as separate
workflows rather than one monolith). Governance came from Unity Catalog and Fabric workspace
integration with catalog-schema segregation, column-level classifications, lineage and access
controls; infrastructure from reusable Terraform modules for Databricks clusters, ADF linked
services, Synapse serverless, Event Hub, storage integration and per-environment config.

### EDF Energy — Energy Data Platform Modernisation (Sep 2024 – Oct 2025)
Lead Data Engineer on a cloud-native modernisation programme covering smart metering, generation
asset and customer analytics datasets.

Designed AWS Databricks ingestion frameworks in Python/PySpark for smart meter readings,
generation asset telemetry, energy trading and customer consumption data from heterogeneous
sources, landing to S3 with schema enforcement and partitioning. AWS Glue jobs applied cleansing,
enrichment, reconciliation and business-rule processing to meter and billing data across Bronze,
Silver and Gold layers. Implemented an **Apache Iceberg** lake on AWS — schema evolution,
partitioning, upserts and validation — to keep the medallion datasets traceable for downstream
analytics and **Ofgem compliance**. Engineered a real-time smart metering stream on Kafka + PySpark
Structured Streaming with checkpointing, event-time processing and Delta Lake as sink, so meter
readings and grid events reach operational dashboards continuously. Scheduling ran on Airflow DAGs
in Amazon MWAA with sensors, retry policies, SLA alerts and parameterised Databricks jobs.
Provisioned workspaces, S3, IAM, Glue, Secrets Manager and networking via Terraform. Mentored the
engineering team on PySpark, SQL optimisation, data modelling, Medallion architecture and GitHub
Actions CI/CD, and owned production release governance for the 6-member team — code reviews,
deployments, release validation, rollback readiness and production approvals.

### Sky — Media & Broadband Data Lakehouse (Jan 2022 – Aug 2024)
Senior Data Engineer building cloud-native ELT pipelines for subscriber analytics, content
performance and operational reporting.

Developed high-volume **Scala Spark** applications on Dataproc using Spark SQL, GCS, BigQuery,
Pub/Sub and Dataflow to process subscriber activity, content viewership and broadband usage, with
optimised joins, partitioning and caching for large-scale workloads. Cloud Composer/Airflow
workflows tied together GCS, Dataflow, Dataproc, BigQuery, Pub/Sub, Cloud Functions and Secret
Manager to automate ingestion, transformation, validation and publication on SLA-driven schedules.
Designed BigQuery analytical datasets — subscriber metrics, content performance, network capacity
and churn — surfaced through Looker for self-service analytics by product and marketing. Tuned
Spark on Dataproc via GCS partitioning, BigQuery connectors, predicate pushdown, skew handling and
executor tuning, using Cloud Monitoring and Cloud Logging to locate bottlenecks. On the warehouse
side, built **dbt** models in Snowflake with staging/mart layers, incremental models, snapshots,
Jinja macros and source definitions applying dimensional modelling to subscriber, billing and
content data — plus dbt tests, docs, lineage and source freshness checks, Snowflake streams,
tasks, clustering, time travel and zero-copy cloning, all deployed through GitHub Actions CI/CD.
